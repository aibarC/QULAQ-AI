## 1. Что сделано

| Часть | Готовая работа |
|---|---|
| Frontend | Адаптивный интерфейс, анимации и регулируемые панели; список 65 диалогов при наличии приватного DEV, языковые группы, поиск, загрузка TXT/JSON |
| Результаты | Чек-лист, баллы, N/A, компактные раскрываемые доказательства, подсветка реплик, XLSX, аудиоплеер и переход к времени |
| Апелляции | Подача пользователем, общая очередь проверяющего, решение с причиной и пересчёт, сохранение исходного ответа |
| Руководитель | Период/месяц, среднее, график по датам с осью 0–100 и линией среднего, повторяющиеся нарушения и примеры |
| Причины обращений | Семь смысловых групп + «Другое» и «Не определено», поиск, исходы, доказательства, ручная Laya для старых результатов |
| Backend | Локальный HTTP API, импорт, задачи анализа, проверка ответа модели и evidence, расчёт баллов кодом, хранение, апелляции, защита от повторного запроса |
| Kimi | Подключение к шлюзу с одноразовым разрешением; prompt и контракт для критериев, причин и coaching; валидация и сохранение советов |
| Laya | Локальный Python worker, закреплённые зависимости и веса, автоматический вызов после Kimi, выбор темы по фрагменту, явные ошибки без потери оценки |

**Советы оператору уже подключены на обеих сторонах.** Если Kimi вернул нарушение и coaching, пользователь видит предлагаемую реплику, объяснение по правилу и исходный фрагмент. Старым результатам советы не придумываются. Напарнику осталось улучшить и проверить качество вывода модели.

## 2. Как получить и запустить

Нужны Git и Node.js 24+. Для новой копии:

```sh
git clone --branch codex/frontend-manager-report https://github.com/aibarC/QULAQ-AI.git QULAQ-AI
cd QULAQ-AI
npm run setup
npm run dev
```

Интерфейс: http://127.0.0.1:5173. Backend: http://127.0.0.1:8000/api/workspace. Общая команда запускает обе части; Vite направляет `/api` на локальный сервер. Порты должны быть свободны.

Для существующей копии сначала `git status`: сохраните собственную работу, не используйте reset/clean. Затем fetch и переключение на актуальную ветку; если она уже существует — обновление через `git pull --ff-only` при отсутствии расхождения. При незавершённых изменениях безопаснее отдельный clone.

Обычный запуск позволяет загружать, просматривать и работать с сохранёнными результатами, но **не разрешает платный анализ Kimi**. Ошибка `EVALUATION_DISABLED` в этом режиме ожидаема.

Для 65 исходных разговоров отдельно получите приватный `dev.json` и положите в корень. Без него используйте загрузку TXT/JSON. Результаты другого компьютера сами не появятся: `.local/server/workspace.json` хранится локально. Аудио для dev-плеера размещается в `.local/audio/<externalId>.mp3`. Эти файлы не передаются через Git.

Для Laya выполните установку из [backend/laya/README.md](backend/laya/README.md): Python-окружение, зависимости, скачивание публичных весов. После установки `npm run dev` подключит её автоматически. Клонирование репозитория само по себе веса не устанавливает.

## 3. Как связаны части и где продолжать

```text
Frontend → /api → backend → Kimi → проверка и scoring
                                      ↓
                   Laya: evidence «Выявление потребности» → группа
                                      ↓
                 локальное хранилище → Workspace → frontend
```

- `frontend/src/lib/adapter.ts` — клиентский API. Сохраняйте обращение через `/api`; адрес и ключ LLM не должны попадать в браузер.
- `backend/src/server.ts` — endpoints и задачи. Frontend отправляет POST `/api/evaluations` с `{recordId, checklistId}`, получает 202 и затем читает Workspace. Не заменяйте это автоматическими повторными POST.
- `backend/src/provider.ts` — вызов Kimi и последующая Laya; `prompt.ts` — инструкции модели; `scoring.ts` — проверка и баллы.
- `frontend/src/lib/types.ts` и `validation.ts` — общий формат и его проверка. Изменения ответа сервера согласовывать с клиентом.
- `backend/src/laya.ts` и `backend/laya/classify.py` — выбор фрагмента и локальная классификация. POST `/api/evaluations/:id/classify-reason` обрабатывает старый результат без вызова Kimi.
- `backend/src/store.ts` — локальное хранение. Один процесс владеет файлом; это не общая многопользовательская база.

Шлюз Kimi: `https://llm.telecom.kz/v1`. Имена серверных переменных: `LLM_BASE_URL`, `LLM_API_TOKEN`. Пользователь сам вводит токен в `.env`; агентам файл читать запрещено. Обычный launcher его не загружает. Порядок одноразового разрешённого теста описан в [backend/README.md](backend/README.md). Не обходите ограничения и не удаляйте квитанции использованных запросов.

Если переносите backend на сервер, сохраните общий формат Workspace и путь `/api` через same-origin proxy. До публичного запуска нужны авторизация, разделение доступа, серверное хранилище, защищённая раздача аудио и отдельная политика разрешения/лимитов вызовов. Простого изменения URL недостаточно.

## 4. Что делать напарнику дальше

1. **Kimi coaching:** улучшить конкретность совета при нарушении. Реплика на языке клиента; объяснение связано с правилом; никакого вымысла о тарифах, сроках или выполненных действиях. При нехватке контекста — `needsContext=true` и `response=null`. Полный JSON и правила в [передаче по модели](docs/TEAMMATE_MODEL_HANDOFF_RU.md).
2. **Проверка качества:** разметить небольшую выборку RU/KZ/EN, отделить контрольную часть; проверять оценку, evidence и совет отдельно. Реальный тест — только по отдельному разрешению пользователя.
3. **Laya:** проверить категории на размеченных разговорах и улучшить выделение потребности. Текущие 5/6 простых примеров и спорный реальный выбор не доказывают надёжность.
4. **Разделение задач моделей:** сейчас Kimi тоже возвращает `contact_reason`, а Laya заменяет категорию. Удаление дублирования — будущая согласованная правка prompt, scorer и тестов; пока не удалять поле самостоятельно.
5. **Аудио:** обеспечить реальные временные смещения текста относительно записи. Текущий отсчёт от первой реплики не гарантирует точного совпадения.
6. После изменений проверить обе части и передать PR с описанием результата. aibarC координирует backend/модели, bagdaulet-dev — frontend/адаптер.

Для своей дальнейшей работы создайте собственную ветку от этой версии, например `git switch -c codex/backend-kimi-coaching`. Не используйте рабочую ветку передачи одновременно с другим разработчиком; не пушьте напрямую в main.

## 5. Проверки и границы готовности

На коммите кода выше прошли **39 frontend + 59 backend тестов**, TypeScript, production build, **5 браузерных сценариев**; ещё 5 сочетаний тестов неприменимы к соответствующему enabled/disabled режиму и пропущены. Остались предупреждения сборки о размере bundle.

```sh
npm test
npm run check
cd frontend
npx playwright test --config=playwright.backend.config.ts
```

Браузерная конфигурация использует Chrome на macOS; на другом устройстве настройте путь. Проверки используют подставной оценщик и не требуют токена.

Два предыдущих реальных теста Kimi подтвердили базовую интеграцию **до добавления coaching**. Новые советы ещё не проверены живым вызовом. Роли демонстрационные, полноценной авторизации нет. Секреты, частные диалоги/результаты, аудио, Python-окружение и веса не включены в GitHub.
