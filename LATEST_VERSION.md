# Последняя переданная версия — frontend + backend

Дата: **8 ноября 2026**. Актуальный источник: [main](https://github.com/aibarC/QULAQ-AI/tree/main).

Включает объединённую работу frontend/backend, изменяемые чек-листы, статистику, рекомендации и последние дополнения:

- загрузка набора по публичной HTTPS-ссылке API с необязательным group_id;
- загрузка PDF с текстовым слоем, TXT и JSON;
- сохранение исходных ID и группы официального JSON, как при импорте API;
- подробный JSON результата рядом с XLSX: критерии, баллы, объяснения, evidence, история пересмотра;
- отключение автоматического восстановления всех DEV-диалогов в API-режиме.

Формат JSON описан в [RESULT_JSON_FORMAT.md](docs/RESULT_JSON_FORMAT.md). Это QULAQ v1, а не неподтверждённая схема приёма организаторов. Старые рабочие ветки и PR #6/#7 — история, не инструкция переключаться на устаревшую версию.

Напарнику начать с [README.md](README.md): там описаны запуск, полный путь добавления/удаления, пример расчёта, правила статистики, разделение типов рекомендаций и карта файлов.

Проверки: **141 unit/HTTP-тест и сборка**; проверены браузерные сценарии загрузки, анализа, экспорта, апелляций и сохранения исходного ID до скачанного JSON. Использовались синтетические данные и подставной провайдер; новые реальные запросы Kimi не выполнялись.

Секреты, диалоги, результаты, аудио и веса Laya передаются отдельно, не через Git. На новом устройстве установите зависимости и Laya по [инструкции](backend/laya/README.md). Обычный запуск открывает ручной режим: вызовы модели происходят по нажатию кнопок анализа/улучшения.

Дальнейшая работа напарника: улучшать и проверять смысловую точность Kimi и Laya. При изменении критериев сохранять версии и снимки старых оценок; не вычислять историю по текущему редактору. Точность рекомендаций и классификации требует отдельной ручной оценки.
