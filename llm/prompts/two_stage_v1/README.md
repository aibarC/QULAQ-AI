# Два отдельных запроса: анализ и пример улучшенного разговора

Этот пакет фиксирует согласованный двухэтапный подход. Оба этапа проверялись с `kimi-k3`. Это сохранённые промпты и контракт подключения; оба этапа подключены в приложении как отдельные действия.

## 1. Кнопка «Проанализировать»

- `system`: точное содержимое `analysis.system.txt`.
- `user`: содержимое `analysis.input_context.txt`, два переноса строки и сериализованный JSON `{"record": record, "factual_ledger": null}`.
- `record`: исходный разговор с `conversation_id`, `language` и `transcript`; у каждой реплики стабильный `id`, `speaker`, `text` и исходный `timestamp`. Допустимые роли включают client/operator/bot/system. ID не перенумеровывать между этапами.
- Ответ модели: `{"results": [...]}` — ровно восемь критериев C1–C8. У каждого `criterion_id`, `status`, `value`, `reason`, `evidence_ids`, `evidence_kind`.
- Проверить JSON, шкалы, условия допустимого N/A, существование ID и порядок границ evidence. Арифметический итог рассчитывает сервер, не модель.
- Сохранить результат вместе с версией промпта и версией/хешем исходного разговора.

Промпт включает сохранённые изменения C6 (убраны упоминания трёх минут и заголовок про скорость) и C7 (конкретный результат считается итогом независимо от эмоциональной формы). Промпт связан с исходным восьмикритериальным чек-листом; не применять его к произвольно изменённой рубрике без адаптации.

## 2. Кнопка «Показать пример правильного подхода»

Запускать по нажатию пользователя после готового анализа, а не автоматически вместе с первым запросом.

- `system`: точное содержимое `conversation_improvement.system.txt`.
- `user`: JSON `{"record": record, "assessment": {"results": saved_results}}`.
- Использовать тот же исходный разговор и именно показанный пользователю сохранённый анализ. Не передавать эталонную разметку или внутренние аудиты.
- Ответ модели: `{"conversation_improvement": "..."}` либо `{"conversation_improvement": null}`.
- Это один общий рекомендуемый сценарий, не восемь полей по критериям. `null` означает отсутствие предложенного улучшения; не подменять его выдуманными советами.

Валидатор второго этапа принимает только это одно поле. Модель не должна возвращать новые оценки. Сервер сохраняет новый текст отдельно, привязав к версии анализа, либо добавляет только `conversation_improvement` в копию ответа. Никогда не заменять `results`, балл, причины или evidence ответом второго этапа. Проверять неизменность старых полей программно.

Если генерация не удалась, первый анализ остаётся доступным; не выдавать ошибку сети за `null` и не считать анализ недействительным. После изменения исходного разговора или анализа прежняя рекомендация устаревает — её нельзя показывать как относящуюся к новой версии. Пример в интерфейсе помечать как рекомендацию ИИ, не как реальную реплику оператора.

## Что проверено и что не обещано

- Тест очистки C6: 10 диалогов; шесть ошибок объяснений исправлены, все десять значений C6 сохранены. Одно контрольное объяснение стало спорным.
- Тест уточнения C7: пять диалогов; одна целевая ошибка исправлена, четыре контрольных C7 сохранены. Изменение C4 пользователь принял в пределах одной ступени относительно уточнённого ориентира. Это не новый полный прогон.
- Отдельная генерация рекомендации: четыре диалога. Две рекомендации пригодны; в одной есть повтор уже известного уточнения, в одной предложено завершение без явного прощания. Эти ограничения сохранены честно: промпт не дорабатывался скрытно после теста.
- Старые оценки в этом отдельном тесте сохранялись программно. Это гарантия способа сохранения, а не доказательство устойчивости модели при повторной оценке.
- Объединённый вариант «оценки + рекомендация одним запросом» в этот комплект не входит.
- Финальный полный прогон выполнен: 65/65 валидных ответов, 479/520 точных совпадений (92,12%); шесть целевых объяснений C6 исправлены. [Отчёт](../../../docs/FINAL_C6_C7_RESULTS.md). Новые API-вызовы требуют отдельного согласования.

## Версионирование

`manifest.json` фиксирует имена, хеши и параметры проверенных вариантов. При следующем изменении создать новую версию; не считать её проверенной только потому, что сохранилось имя модели. Не коммитить реальные диалоги, аудио, ответы с приватными данными или ключи. API вызывать на сервере; секрет не отправлять браузеру.
