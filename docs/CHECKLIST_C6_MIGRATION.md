# Обновление сохранённого C6

При загрузке существующего workspace сервер обновляет C6 только в чек-листе `official-cqa`, если все поля критерия (включая вес, тип, N/A и шкалу) точно совпадают с прежним стандартом. Убираются «скорость» из названия и фраза о трёх минутах из описания. Версия чек-листа увеличивается на один, изменение атомарно сохраняется до запуска сервера. Повторная загрузка ничего не меняет.

Любое пользовательское изменение C6, включая вес, оставляет его нетронутым. Копии с другим ID не обновляются. Изменения других критериев сохраняются. Исторические оценки, их снимки правил, результаты, суммы и апелляции не переписываются. Новые хранилища сразу получают чистый стандарт C6. Миграция не запускает переоценку или модель.

## Проверка интеграции

Путь уже реализован: ChecklistEditor → POST /api/checklists (проверка версии и сохранение) → POST /api/evaluations (последняя сохранённая версия выбранного ID) → фиксированный снимок задания → prompt/валидация/расчёт → EvaluationPanel. Несохранённый черновик не участвует. При нескольких чек-листах применяется выбранный в карточке, а не произвольный последний отредактированный. Изменение правил во время запроса действует только на следующий запуск.

Проверки этой правки:

- TypeScript backend и production build frontend: успешно.
- Модульные/HTTP-тесты: 55 frontend + 89 backend, без ошибок.
- Расширенный Playwright-тест: добавление правила весом25, новый анализ, удаление, новый анализ, проверка весов/формулы и неизменности исторического снимка после reload. Синтетический провайдер, без шлюза.
- Два реальных ручных действия в автоматизированном браузере через локальные frontend/backend и kimi-k3: удаление C7 → v2,7 результатов,100/100; затем добавление правила адреса сайта весом25 → v3,8 результатов,66/100. Новое правило true,25баллов; C7 отсутствует в обоих. Всего ровно2 шлюзовых запроса, повторов нет. Результаты прошли штатную валидацию backend, совпали с сохранёнными правилами и отображением страницы; reload сохранил результат, прежний снимок не изменился.

Во втором случае применимые веса составили100 (C3=N/A), набрано20+15+6+25=66. Это проверка применения пользовательских весов и состава, не утверждение об улучшении качества оператора или метрики модели. C6 в обоих реальных ответах обоснован ясностью/последовательностью без скорости первой реакции.

Приватные транскрипты, запросы, ответы и скриншоты проверки остаются в игнорируемой `.local/checklist-live/` и не входят в Git. Реальное рабочее хранилище пользователя не подменялось. Развёртывание в основной сервис требует принятия ветки и перезапуска backend; фонового пересчёта старых оценок не происходит.
