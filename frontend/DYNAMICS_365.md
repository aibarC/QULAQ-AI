# Подготовка QULAQ к Dynamics 365

## Что требует задание

Student Guide v3, страница 1: интерфейс на HTML, CSS и JavaScript с возможностью дальнейшей адаптации как HTML-компонент Dynamics 365. Подключение к tenant, Dataverse, лицензия Microsoft или PCF не названы обязательными условиями демонстрации. Регистрация и вход для демонстрации не нужны.

React/TypeScript — инструменты разработки. `npm run build` создаёт статические HTML/CSS/JavaScript в dist. В Vite установлена относительная база `./`: ресурсы сборки не привязаны к корню домена. Маршруты используют hash, поэтому не требуют серверного перенаправления для каждой карточки.

## Граница адаптации

UI и сервер разделены клиентским адаптером. Сейчас /api — адрес сервера того же origin; он НЕ станет автоматически API QULAQ на домене Dynamics. До переноса aibarC должен согласовать транспорт, авторизацию и серверное хранение. Секреты организаторов/модели нельзя помещать в HTML-ресурс.

Нынешний DEV-импорт /__local/dataset работает только в локальном Vite. dev.json не включается в production-сборку. Учебное sessionStorage не является постоянным хранилищем Dataverse.

## Следующий этап при появлении среды Dynamics

1. Выбрать с владельцем Dynamics HTML web resource либо PCF. Текущее задание не требует реализации PCF.
2. Создать ресурсы в solution с согласованным префиксом и сохранить относительные связи HTML/JS/CSS. Проверить разрешённые типы ресурсов: файлы шрифтов woff2 из текущей сборки потребуют отдельного решения (системный шрифт либо допустимый способ доставки).
3. Реализовать отдельный транспорт к backend/Dataverse. Для контекста формы использовать документированные API Microsoft, не читать DOM родительской страницы.
4. Настроить размещение и разрешения в конкретной среде, проверить iframe/политику встраивания. Локальный сервер сохраняет X-Frame-Options: DENY; снимать защиту разработки ради предположительного встраивания не нужно.
5. Проверить в реальной форме: размеры, клавиатуру, запись и повторное чтение оценки, апелляцию, смену записи, RU/KZ/EN. Локальная сборка не доказывает совместимость с Dynamics.

## Что ещё нужно для хакатона

Frontend содержит редактор чек-листа, доказательства, учебную оценку и апелляции. Реальная оценка, пересчёт и постоянное хранение требуют backend. Учебный сценарий не подтверждает готовность реального сервиса.

Официальный чек-лист перераспределяет веса при N/A и сохраняет максимум100; пользовательский отдельный отчёт с N/A=0 не следует смешивать с официальным режимом. Веса семи балльных критериев10/15/20/20/15/15/5; грубые ошибки отдельно. Оценивать нужно оператора; бот и система — контекст.

При сдаче требуется открытый Git-репозиторий, README запуска, демонстрация до5мин, применение изменённого критерия через UI и обработка контрольного набора. Публикация и изменение видимости репозитория этим документом не выполняются. Для платной модели указываются название и приблизительная стоимость одной полной оценки.
