# QULAQ frontend

Интерфейс контроля качества диалогов: React + TypeScript + Vite, собственные CSS-компоненты, локально поставляемый шрифт Manrope. В рабочей копии доступны API-режим с новым локальным сервером и отдельный frontend-only режим с Excel-предпросмотром и учебным демо. Внешняя Kimi по умолчанию отключена. Базовая связка проверена двумя единичными запросами; качество новых советов ещё не подтверждено. Установленная Laya работает локально.

## Режимы запуска

Для полной локальной связки выполните `npm run setup` и `npm run dev` **из корня репозитория**. Новый сервер описан в [backend/README.md](../backend/README.md): он хранит Workspace и обслуживает `/api`, но LLM отключён до отдельного разрешения пользователя. Корневой `.env` агентам читать запрещено. Базовые единичные проверки шлюза проводились ранее; новые задачи coaching проверены пока на синтетических ответах.

Команды из этой папки ниже запускают отдельный local-предпросмотр Excel, если `VITE_API_BASE_URL` не задан. В API-режиме загрузка TXT/JSON сохраняет диалоги на сервере и открывает карточку; запуск анализа — отдельное действие. Корневой launcher сам настраивает API/proxy для Vite и не требует менять frontend `.env.local`.

## Напарнику: с чего начать

1. Прочитать корневые [README](../README.md), [AGENTS](../AGENTS.md), [CONTRIBUTING](../CONTRIBUTING.md) и [TEAMMATE_UI_BRIEF](../TEAMMATE_UI_BRIEF.md), затем этот файл.
2. Актуальная полная версия frontend и backend находится в `codex/frontend-manager-report`. Предыдущие PR — история разработки. Перед началом прочитайте [передачу задач по модели](../docs/TEAMMATE_MODEL_HANDOFF_RU.md). Не переключайте ветки поверх незавершённой работы: используйте отдельный clone/worktree.
3. Выбрать режим запуска. Для набора DEV получить приватный `dev.json`; Excel-разметка нужна только для frontend-only предпросмотра. API-режим позволяет загрузить собственный TXT/JSON без DEV, а учебное демо доступно в отдельном local-режиме.
4. Просмотреть [типы](src/lib/types.ts), [адаптер](src/lib/adapter.ts) и [валидацию](src/lib/validation.ts). Это граница интеграции; компоненты работают с `Workspace`, а не с сырым ответом LLM.
5. Проверить новый сервер по контракту ниже и пройти сценарий с подставным оценщиком. Реальный запрос модели требует отдельного указания пользователя. Слияние в `main` координируется через PR.

## Что изменилось и что подключать напарнику

Текущая рабочая копия включает автоматическую загрузку DEV, сворачиваемые языковые группы, локальную загрузку TXT/JSON и просмотр готовой разметки. Она сохраняет клиентский API-контракт и учебный цикл. В интеграционной ветке добавлен локальный сервер; запускайте связку из корня. Реальный LLM остаётся отключённым, а проверка ответа внешнего шлюза ещё не выполнена.

- `SplitWorkspace.tsx`: разделитель, разворачивание, сохранение ширины; на узком экране адаптивное расположение.
- `Shared.tsx` / `transcript-motion.css`: переход к доказательству и фокус реплик.
- `EvaluationPanel.tsx`: фиксированные критерии и результаты Excel только для чтения; источник отделён от учебной и серверной оценки.
- `reference-preview.ts`: загрузка подготовленной разметки и отдельный расчёт баллов предпросмотра по фиксированному снимку правил.
- `conversation-list.ts`: порядок RU/KZ/EN и естественная числовая сортировка ID.
- `UploadTranscript.tsx`: выбор/перетаскивание TXT/JSON, проверка формата и размера, предпросмотр; в API-режиме отдельная отправка локальному серверу, в local-режиме только память компонента.
- `export-evaluation.ts`: экспорт результата, критериев и транскрипта в XLSX.
- `MotionSettings.tsx`: интенсивность движения; предпочтение хранится в текущей вкладке.
- `ListeningStage.tsx`: интерактивное знакомство с учебным процессом.
- `CommandMenu.tsx`: поиск по разделам и загруженным диалогам.
- `DESIGN.md`: текущие цвета, движение и источники; `DYNAMICS_365.md`: границы будущей адаптации.

В frontend-only режиме с приватными материалами дождитесь списка 65 разговоров и откройте «Посмотреть результат». Для учебной апелляции используйте «Учебный пример»: 85/100 и 100/100 — заранее заданные значения. В API-режиме импортированные разговоры не получают готовых Excel-оценок: карточка показывает чек-лист, а реальный анализ заблокирован до отдельного разрешения.

## Запуск

Для общей связки нужен Node.js 24+ и npm. Следующие команды из папки `frontend` запускают только интерфейс:

```sh
npm ci --ignore-scripts
npm run dev
```

Для frontend-only просмотра набора и Excel-результатов нужны два приватных файла, полученных отдельно:

```text
<корень репозитория>/dev.json
<корень репозитория>/.local/reference/annotations.json
```

`dev.json` содержит `data.records` с 65 разговорами. `annotations.json` — подготовленная карта ID → ответы и объяснения из предоставленного Excel; браузер не читает исходную книгу напрямую. Ответы проверяются в `src/lib/reference-preview.ts`.

Если получена исходная книга, подготовить JSON можно скриптом. Нужны Python 3.10+ и установленный `openpyxl`. Из папки `frontend`:

```sh
python3 scripts/prepare-reference-preview.py /absolute/path/to/workbook.xlsx
```

Заменить путь на путь к выданной книге. Скрипт читает листы `Разметка*` с заголовками в строке 6 и данными начиная со строки 7, сверяет все 65 ID с DEV и атомарно сохраняет результат в `../.local/reference/annotations.json`. Дубликаты, пропущенные ID и недопустимые ответы отклоняются до записи. Лист «Спорные» не используется; внутренние префиксы `СПОРНО` убираются из пояснений. Исходная книга остаётся неизменной; содержимое ячеек и транскриптов не выводится в терминал. При необходимости доступны `--dataset /path/dev.json` и `--output /path/annotations.json`; стандартные пути вычисляются от папки проекта, независимо от текущего каталога. Для установки зависимости используйте `python3 -m pip install openpyxl` в своём Python-окружении.

В этой рабочей копии `dev.json` исключён через `.git/info/exclude`, а `.local/` — через общий `.gitignore`. Локальное исключение не переносится при clone. В новой копии до размещения DEV-файла выполните из корня:

```sh
printf '\n/dev.json\n' >> "$(git rev-parse --git-path info/exclude)"
git check-ignore -v dev.json .local/reference/annotations.json
```

Исходную книгу и PDF держать вне репозитория либо в исключённой папке `data/private/`. Не добавлять настоящие транскрипты или разметку в fixtures. После начальной загрузки workspace local-режим автоматически импортирует DEV, если реальных записей ещё нет. Повторный импорт не создаёт дубликаты. При ошибке остаются кнопка повтора и доступное учебное демо; ошибки разметки показаны отдельно.

Открыть http://127.0.0.1:5173. Из корня `npm --prefix frontend run dev` запускает только интерфейс; `npm run dev` запускает интерфейс вместе с API. Не запускать оба варианта одновременно на одном порту.

```sh
npm run build     # TypeScript + production bundle
npm test          # проверки адаптера, версий, данных и экспорта
npm run test:e2e  # browser journeys; нужен установленный Google Chrome
```

Основные E2E-тесты автоматически запускают dev-сервер, если порт 5173 свободен. Перед ними остановить общую API-связку на этом порту: local-сценарии не должны подключаться к серверу в другом режиме. Для реального локального списка и предпросмотра нужны приватные `../dev.json` с 65 записями и `../.local/reference/annotations.json`. На macOS используется стандартный путь Google Chrome; основной Playwright config позволяет задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` для другого расположения браузера.

Отдельный `npm run test:e2e -- --config playwright.backend.config.ts` поднимает настоящий локальный HTTP-сервер с временным хранилищем и синтетическим оценщиком на отдельных портах. Он проверяет API-загрузку, результат, evidence, апелляции и восстановление. Никакой тест не разрешает вызов реального LLM-шлюза и не требует чтения `.env`; результаты этих проверок не доказывают качество модели.

`npm run preview` показывает собранный bundle. Приватные DEV-данные и разметка доступны только через dev-сервер: read-only GET `/__local/dataset` и `/__local/annotations`. Они читаются с диска и не включаются в production bundle. Для production-режима нужен backend; запуск preview не поднимает эти локальные маршруты.

## Что работает локально

Требование о будущем HTML-компоненте Microsoft Dynamics 365 и границы адаптации разобраны в [DYNAMICS_365.md](DYNAMICS_365.md). Статическая сборка использует относительные пути ресурсов; подключение к реальной среде Dynamics пока не реализовано и не требуется для демонстрации по Student Guide.

### Обновлённый интерфейс

В карточке разговора панели транскрипта и оценки можно раздвигать разделителем (мышь либо стрелки, Home/End), разворачивать отдельно и возвращать к совместному виду. Ширина запоминается в текущей вкладке. На телефоне панели идут последовательно. Выбор доказательства возвращает транскрипт, выделяет нужные реплики и приглушает остальные; выделение можно снять. Внизу страницы доступна настройка «Движение»: полное, умеренное или выключенное. Системное уменьшение движения имеет приоритет. Эти функции не меняют баллы и не запускают обработку данных.

На компьютере навигация по умолчанию расположена сверху. «Меню сбоку» и «Меню сверху» меняют её положение; выбор сохраняется в текущей вкладке. На телефоне используется выдвижное меню. Текущая палитра — pearl/violet/cyan, с полупрозрачной навигацией и объёмной градиентной сценой.

Пустое состояние `ListeningStage` содержит движущуюся объёмную форму, реакцию на указатель, паузу и три интерактивных этапа разбора. Это иллюстрация учебного процесса, не визуализация аудио или реальной AI-оценки. Кнопка «Исследовать пример» открывает существующий учебный диалог. При reduced motion движение отключается. Новых библиотек и внешних запросов для анимации нет.

Дизайн и правила движения описаны в [DESIGN.md](DESIGN.md). Быстрый поиск в верхней панели открывается также по `⌘K` / `Ctrl+K`: ищет разделы, ID и текст уже загруженных разговоров. В режиме проверяющего доступны только обращения и его раздел. Переходы сохраняют защиту несохранённых правок.

В local-режиме список сгруппирован RU → KZ → EN; внутри каждой группы ID отсортированы естественно, с учётом чисел. Все 65 записей текущего набора помещаются на одну страницу. Кнопки в заголовках групп независимо сворачивают и разворачивают их строки; настройки движения учитываются. Поиск ID и фильтры языка/канала доступны; колонка «Источник результата» показывает «Excel · предпросмотр», баллы видны только внутри открытого результата. Поле DEV скрыто: «Загрузить набор»/«Обновить набор» используют группу DEV автоматически. Состояния серверных запусков не подменяются Excel-разметкой: статусный обзор и фильтр доступны только в API-режиме. Две кнопки рядом с поиском меняют плотность строк.

- Роли «Пользователь» и «Проверяющий», отдельная навигация, ссылки на диалоги/запуски/обращения.
- Автоматическая загрузка `../dev.json` при отсутствии реальных записей; кнопка «Обновить набор» позволяет перечитать файл. Форма организаторов `data.records` проверяется. ID сообщения связан с исходным индексом реплики, не с порядком отфильтрованного списка.
- Таблица с поиском ID, языковыми группами и фильтрами; пагинация появляется только при количестве записей больше 65. «Посмотреть результат» открывает полный транскрипт и готовый разбор. Поиск внутри текста и аудиоплеер работают независимо; отказ аудио не скрывает текст.
- Чек-листы: создание, копирование, версии, редактирование правил/весов/типов/шкал/N/A, добавление и удаление критериев, валидация и защита несохранённых правок.
- DEMO-001: отдельный искусственный разговор; демонстрационный ответ по восьми критериям, доказательства с переходом к реплике, апелляция, очередь, подтверждение/изменение с причиной, история и исходный результат.
- Состояния пустого списка, загрузки, ошибки, повторной попытки; клавиатурная навигация и модальный диалог; адаптация к узкому экрану; уменьшение анимаций при prefers-reduced-motion.

### Загрузка собственного TXT/JSON

В API-режиме кнопка «Открыть для анализа» отправляет проверенный набор на `/api/datasets/upload` и открывает первую карточку. Импорт не вызывает модель. TXT для отправки должен содержать явные роли `Клиент:`/`Оператор:` (также поддерживаются английские подписи); время необязательно. После сохранения данные остаются в локальном хранилище сервера. В local-режиме действует предпросмотр, описанный ниже.

Над набором разговоров находится блок «Загрузить транскрипт». Он принимает один UTF-8 файл `.txt` или `.json` размером до 5 МБ через выбор файла или drag-and-drop. «Читаем файл…» остаётся видимым минимум около 400 мс, без выдуманного процента прогресса или запуска анализа. Затем открывается сворачиваемый предпросмотр. Ошибка замены сохраняет предыдущий корректный файл; «Удалить файл» очищает его и отменяет незавершённое чтение.

- TXT: выбор языка RU/KZ/EN, исходный текст и число непустых строк. Участники и временные метки не выдумываются.
- JSON: тот же формат DEV, который проверяет `parseDataset`: `isSuccess: true`, `data.dataset_group_id`, `data.total_records`, `data.records`. Группа берётся из файла. Язык, участники и время каждой реплики сохраняются; диалог выбирается в списке предпросмотра. Для длинных транскриптов дополнительные реплики раскрываются кнопкой. Ссылки `audio_url` из загруженного JSON не воспроизводятся и не запрашиваются.

До отдельного нажатия «Открыть для анализа» файл находится только в памяти компонента. В API-режиме отправляются проверенные записи, а не исходный бинарный файл: группа становится `UPLOAD`, ID включают отпечаток содержимого для повторяемого импорта, `audio_url` сбрасывается в null. После успешного ответа записи входят в серверный Workspace и переживают reload/перезапуск. Удаление файла из блока предпросмотра не удаляет уже сохранённые на сервере разговоры.

В frontend-only local-режиме блок **не отправляет файл на сервер, не добавляет диалоги в Workspace и не сохраняет их в браузерное хранилище**. «Анализировать» здесь недоступно. Уход из раздела, перезагрузка или удаление убирает только временный предпросмотр. Ни чтение файла, ни API-импорт не вызывают модель.

## Предпросмотр Excel и отдельное учебное демо

В local-режиме «Посмотреть результат» не вызывает `adapter.evaluate`. Ответы и объяснения взяты из подготовленной Excel-разметки; баллы и итог рассчитаны для предпросмотра по фиксированному снимку правил из материалов хакатона. Это не новый вывод модели и не подтверждённая серверная оценка. Карточка явно сообщает: «Предпросмотр из Excel — backend не запускался».

В карточке видны все восемь критериев, их типы, веса, условия N/A и шкалы. Предпросмотр доступен только для чтения: нет запуска оценки, смены его правил или отправки апелляции. Редактор чек-листов остаётся отдельной функцией и не изменяет снимок Excel. Если разметки нет или она не загрузилась, показаны соответствующее сообщение и повтор; вымышленный результат не создаётся. Подтверждённый результат сервера имеет приоритет перед предпросмотром.

Preview не добавляется в `workspace.evaluations` и не сохраняется как серверная оценка. Ответы разметки остаются в памяти страницы; после reload файл перечитывается.

Маршрут карточки в интерфейсе — `#/dialog/<encodeURIComponent(conversation.id)>`. Для сохранённого запуска используется `?evaluation=<encodeURIComponent(evaluation.id)>`. Это ID из клиентского `Workspace`, не произвольное имя файла. Отдельного HTTP-маршрута `/results` клиент не вызывает: подтверждённые серверные оценки ожидаются в `Workspace.evaluations`, Excel-preview строится отдельно.

### Экспорт XLSX

Кнопка экспорта создаёт три листа:

- **«Результат»** — ID диалога, язык, источник, снимок чек-листа и итог;
- **«Баллы по критериям»** — ответ, баллы, объяснение, доступные доказательства и причина N/A;
- **«Транскрипт»** — все реплики с исходными ID, временем и участником.

Источник Excel явно указан в выгрузке; время предпросмотра не выдаётся за время серверной оценки. Экспорт не запускает модель и не отправляет файл в GitHub. Для учебной или серверной оценки экспорт использует соответствующую подпись источника.

### DEMO-001

DEMO-001 содержит только придуманный текст. Каждый его результат помечен «Демонстрационная оценка — ИИ не запускался». Исходный fixture — 85/100. При изменении ответа «Эмпатия» с «Нет» на «Да» показывается заранее заданный fixture 100/100. Это демонстрация интерфейса, а не вычисление серверной формулы. Для изменённых правил и неподдержанных учебных решений итог `null` и видимое сообщение о необходимости расчёта сервером. Новые критерии действительно сохраняются, но модель локально не запускается.

В frontend-only режиме учебные чек-листы, результаты и обращения DEMO-001 сохраняются в `sessionStorage` текущей вкладки и восстанавливаются после reload. Настоящие транскрипты остаются в памяти; DEV перечитывается с локального диска. В API-режиме Workspace хранится отдельно на сервере в `.local/server/workspace.json`; данные этих двух режимов не объединяются. Переключатель ролей не является авторизацией.

## Подключение backend

Контракт ниже реализован локальным сервером в `backend/`. Запуск и безопасный режим описаны в [backend/README.md](../backend/README.md). Вызовы модели по умолчанию запрещены; ответ `503/EVALUATION_DISABLED` отображается как явное пояснение, без вымышленных баллов и без повторного POST.

Старые ветки `codex/backend-annotation-kit` (`98cc9d6`) и `codex/backend-prompt-na` (`6373e6c`) содержат материалы разметки/промптов; новый Workspace API добавляется в `codex/frontend-manager-report`. Шлюз модели `/chat/completions` остаётся отдельной внешней зависимостью и не заменяет API приложения.

HTTP-адаптер ожидает полный подтверждённый `Workspace` после каждого запроса (типы в `src/lib/types.ts`). Ошибки не переключают его на mock или Excel-preview. В API-режиме локальная разметка не загружается. Анализ импортированного диалога отправляет его ID и выбранный чек-лист, открывает карточку и показывает только подтверждённый новый результат.

| Метод | Путь                        | Тело                                                |
| ----- | --------------------------- | --------------------------------------------------- |
| GET   | `/api/workspace`            | —                                                   |
| POST  | `/api/datasets/import`      | `{ groupId }`                                       |
| POST  | `/api/datasets/upload`      | Проверенный DEV-объект с группой `UPLOAD`           |
| POST  | `/api/checklists`           | `Checklist`                                         |
| POST  | `/api/evaluations`          | `{ recordId, checklistId }`                         |
| POST  | `/api/appeals`              | `{ evaluationId, criterionId, comment }`            |
| POST  | `/api/appeals/:id/decision` | `{ action: 'confirm' \| 'change', answer, reason }` |

`Workspace = { conversations, checklists, evaluations, appeals }`. Ответы проходят проверку структуры, ID и связей, допустимых ответов и evidence. `Evaluation` содержит снимок чек-листа, `originalTotal`, `total`, `grossViolation`, `results`; результат критерия содержит `originalAnswer`, `answer`, `points`, `explanation`, `evidence` и при пересмотре `override`. `null` в answer — N/A, в total — итог отсутствует. В production результат обязан иметь `demo:false`.

Новый запуск должен завершаться новым подтверждённым `Evaluation` для запрошенных `recordId` и `checklistId`. Сам по себе статус `evaluated` вместе со старой оценкой не подтверждает завершение нового анализа.

При `status:'evaluating'` после POST адаптер опрашивает GET workspace до двух минут. При timeout последнее подтверждённое состояние сохраняется; новый POST автоматически не отправляется. На странице доступны read-only обновление статуса и возобновление опроса после reload. Сервер отвечает за дедупликацию импорта, стабильные ID, версии, вычисление баллов/N/A, атомарность решений и хранение. Повторные мутации после сетевой ошибки требуют сверки текущего состояния.

При общем `npm run dev` из корня настройки API уже передаются Vite. Только для раздельного запуска скопировать **frontend** `.env.example` в **frontend** `.env.local` и включить:

```dotenv
VITE_API_BASE_URL=/api
QULAQ_API_TARGET=http://127.0.0.1:8000
```

Перезапустить Vite. Proxy разрешает только localhost/127.0.0.1 с явным портом. В production `/api` обслуживается на том же origin. Ключи модели и подписанная ссылка организаторов никогда не передаются frontend и не используются в VITE_* переменных.

Proxy сохраняет префикс `/api`: backend на `QULAQ_API_TARGET` должен обслуживать перечисленные `/api/...` пути либо потребуется согласованное изменение маршрутизации. Эти env-переменные не запускают сервер. Чтобы вернуться к локальному предпросмотру, убрать/закомментировать `VITE_API_BASE_URL` и перезапустить Vite. При включении API нельзя рассчитывать на локальный `dev.json` как запасной источник при ошибке сервера.

Корневой `.env` отличается от frontend-конфигурации: он предназначен только для серверных имён `LLM_BASE_URL` и `LLM_API_TOKEN`. Агентам запрещено его читать. Обычный серверный старт его не загружает; загрузка возможна только после будущего явного разрешения пользователя на один тест и специального флага. Одноразовая квота записывается до запроса, сохраняется на диске и не восстанавливается после ошибки или перезапуска. Подробности — [backend/README.md](../backend/README.md#состояние-модели-и-секреты).

## Проверочный сценарий для показа

У сохранённой оценки сразу под итогом есть заметная кнопка **«Подать апелляцию»**: выберите критерий и укажите причину. Кнопки «Оспорить» доступны также у свёрнутых критериев. Отправленное обращение сохраняется на сервере, появляется в «Моих апелляциях» и в очереди проверяющего; повторная кнопка ведёт к существующему обращению. Проверяющий по умолчанию видит ожидающие решения. В API-режиме очередь обновляется при открытии, возврате в окно и каждые 15 секунд, пока вкладка видима. Решение сохраняет исходную оценку и обновляет финальный результат без нового вызова LLM. Excel-предпросмотр остаётся только для чтения.

Ниже — frontend-only сценарий. Для серверного HTTP-пути используйте отдельный синтетический тест из раздела запуска; обычный API-сервер не создаст оценку при выключенном LLM.

1. Открыть приложение с приватными материалами: автоматически видны 65 разговоров, 60 чатов и 5 звонков. Проверить группы RU → KZ → EN, их независимое сворачивание и числовой порядок ID. Открыть «Посмотреть результат», увидеть источник Excel, восемь критериев и объяснения; скачать XLSX и проверить три листа. Баллов в таблице быть не должно.
2. Вернуться и открыть «Учебный пример». Нажать «Оценить», дождаться результата 85/100.
3. В «Эмпатия» нажать доказательство, затем «Оспорить», написать причину и отправить.
4. Переключить роль на «Проверяющий», открыть обращение. Выбрать «Изменить оценку» → «Да», указать причину, сохранить. Учебный итог — 100/100.
5. В роли пользователя найти решение в «Моих апелляциях», открыть соответствующий результат. Исходный учебный результат и причина пересмотра доступны. Reload сохраняет учебное состояние.
6. В «Чек-листах» создать/изменить правило и сохранить. Новая версия не меняет снимок старого результата. Сервер применяет снимок выбранной версии к новому запуску; применение реальной моделью ещё требует разрешённой проверки.
7. В списке открыть собственный синтетический TXT/JSON: увидеть чтение и предпросмотр, свернуть/развернуть его, проверить ошибку неверного файла и удалить. Список разговоров не меняется, серверная оценка не запускается.

## Следующие шаги для aibarC

- Проверить новую локальную реализацию `backend/` и согласовать её с будущим размещением.
- После отдельного разрешения пользователя выбрать точное имя модели и выполнить только один реальный тест. Не читать `.env` агентами и не вызывать список моделей автоматически.
- Сверить качество RU/KZ/EN и фактический ответ шлюза; тестовый оценщик не доказывает качество LLM.
- Перед публичным размещением добавить настоящую авторизацию, разграничение пользователей, производственное хранилище и правила обработки данных. Текущий сервер ограничен одним устройством.

### Как разделить следующие изменения

**bagdaulet-dev:** компоненты, визуальные состояния, формы, навигация и преобразование API в клиентский контракт. **aibarC:** сервер, модель, scoring, хранение, авторизация, общая конфигурация и интеграция. Изменения контракта согласовать до параллельных правок. Не переносить mock-оценки в production и не исправлять расхождения API вымышленными данными.

### Если что-то не запускается

- Ошибка импорта в local-режиме: проверить наличие `dev.json` в корне и запуск именно `npm run dev`, затем нажать «Повторить загрузку».
- Ошибка предпросмотра: проверить `.local/reference/annotations.json` и соответствие ID данным DEV; нажать «Повторить загрузку результатов». При отсутствии файла учебный DEMO-001 остаётся доступен.
- Ошибка подключения API: проверить запущенный backend, порт `QULAQ_API_TARGET`, ответ GET `/api/workspace` и перезапуск Vite после изменения env.
- Ошибка валидации ответа: сравнить ответ с `types.ts` и `validation.ts`; исправить контракт/маппинг, не отключать проверку данных.
- Порт занят: остановить прежний dev-сервер либо выбрать другой порт для ручного просмотра; E2E ожидают 5173.
- После закрытия вкладки исчезло учебное состояние: это ожидаемая граница sessionStorage. Постоянное хранение обеспечивает backend.

### Время и переход к записи

В интерфейсе метки показываются как `HH:MM:SS` относительно первой реплики. Исходные timestamp сохраняются в данных, XLSX и подсказке метки. Нажатие на доказательство выделяет текст и переводит доступный аудиоплеер к соответствующему смещению; нажатие на метку реплики также перематывает запись. При первом переходе плеер загружает метаданные, затем применяет выбранную позицию. Автоматического начала воспроизведения нет. Недоступная запись и выход за её длительность показываются явно.

Начало первой реплики принято за нулевую точку аудио: это приближение, пока backend не передаёт проверенное смещение начала записи. Механика перемотки проверена на синтетическом WAV и скачанном MP3. Исходная ссылка p4-ru-001 ведёт на HTML-плеер, а не непосредственно на звук; подробности локального подключения ниже.

Обновление локальной проверки аудио: MP3 p4-ru-001 скачан из `<source>` страницы-плеера и хранится только в `.local/audio/p4-ru-001.mp3` (игнорируется Git). В dev-режиме интерфейс проверяет наличие `/__local/audio/<externalId>.mp3` и использует локальную запись; Vite поддерживает HEAD и byte ranges. Production-сборка не содержит файл или этот маршрут. На настоящем MP3 проверены переход к 259.825 секунды и дальнейшее воспроизведение. Длительность плеера — 312.26 секунды, последняя метка транскрипта относительно первой — около 320.21 секунды; точное соответствие слов времени не подтверждено. Метки вне длительности не перематывают плеер и показывают предупреждение.

### Управление плеером

Плеер показывает прошедшее время и длительность, плавно перемещает индикатор при переходе по доказательству, поддерживает паузу, ±10 секунд, скорость 0.75–2× и управление шкалой с клавиатуры. Настройка уменьшения движения отключает анимации. Звук переходит сразу к выбранной секунде; визуальное движение шкалы не задерживает перемотку.

## Режим руководителя

Третья роль «Руководитель» открывает отчёт за текущий месяц с выбором периода и языка. Отчёт строится по сохранённым оценкам Workspace API, не вызывает модель и не использует учебные результаты или Excel-предпросмотр. Дата периода — дата анализа в Asia/Almaty, а не дата звонка. На один разговор берётся последний анализ внутри периода. Баллы учитывают уже сохранённые решения апелляций; это текущая сводка, не исторический снимок до пересмотра.

Доступны средний балл, размер выборки, дневная динамика и повторяющиеся нарушения с переходом к тексту и доказательствам. Дни без оценок не превращаются в нулевые баллы; N/A исключается из знаменателя соответствующего критерия. Разные версии правил считаются раздельно. При малой выборке выводится предупреждение; пустой период не заполняется искусственными числами. Режим доступен только для просмотра, переключатель ролей по-прежнему не является авторизацией.

В отчёте также доступен раздел «Причины обращений»: семь смысловых групп, «Другое», «Не определено», отдельное состояние без классификации, поиск и фильтр исхода. Категории присваивает модель в будущем разрешённом анализе, а не frontend по ключевым словам. Отчёт не запускает LLM. Старые результаты сохраняются без выдуманных категорий. Основная причина учитывается один раз, вторичные темы — только теги. Исход «Не решено» требует явного основания; отсутствие ответа о решении показывается как «Неясно». Контракт и ограничения: `docs/CONTACT_REASONS_PROPOSAL_RU.md`.

График руководителя использует фиксированную ось Y 0–100 с делениями через 20, ось дат и координатную сетку. Бирюзовая пунктирная линия — средний балл всех выбранных диалогов с числовым итогом (не среднее дневных средних). Фиолетовая линия соединяет только соседние дни с данными; пропуски остаются разрывами. Наведение или стрелки клавиатуры показывают дату, средний балл и количество диалогов. Подробные значения доступны в раскрываемой таблице. Основные показатели и отступы отчёта уплотнены для более компактного просмотра.

### Пример ответа оператору

Нарушенный критерий может содержать `coaching`: предложенную реплику `response`, пояснение связи с правилом `explanation`, флаг `needsContext` и ID исходных реплик `messageIds`. Блок «Как можно было ответить» доступен в результате, апелляции и примере руководителя. Он явно отделён от транскрипта; нажатие «Показать исходный фрагмент» выделяет исходные реплики. Длинный пример раскрывается отдельно. Если проверяющий отменил нарушение, совет скрывается без удаления исходного результата.

Совет запрашивается вместе с анализом и не вызывает отдельный LLM-запрос. При недостатке бизнес-правил модель должна вернуть `needsContext=true`, `response=null` и указать недостающий контекст. Старые результаты без совета показывают это состояние явно. Смысловое качество советов реальной модели пока не проверялось; синтетические тесты подтверждают контракт и интерфейс, а не корректность рекомендаций.

## Laya: локальные категории после Kimi

Установленная Laya Multilingual автоматически классифицирует причину после успешного анализа Kimi. Она использует evidence критерия «Выявление потребности» и ближайшие соседние реплики. В карточке причины показаны источник «Laya · локально» и исходный фрагмент. Для уже существующих анализов есть кнопка «Определить причину · Laya»; она не запускает Kimi и не пересчитывает баллы. Ошибка локальной модели показана отдельно и не подменяется «Не определено».

Установка и точные ограничения — `backend/laya/README.md`. Runtime/веса лежат в `.local/` и не отправляются в Git. `npm run dev` автоматически подключает Laya, если окружение и веса установлены, но сохраняет запрет внешних запросов Kimi. Категория автоматически выбранная, не подтверждённая человеком. В короткой проверке RU/KZ/EN 5 из 6 примеров распределены ожидаемо; казахский пример восстановления пароля дал ошибку. На p4-ru-001 сохранён реальный локальный выбор «Технические проблемы», который требует смысловой проверки: обсуждение помощи брокера неоднозначно. Эти проверки не подтверждают качество на всех разговорах.
