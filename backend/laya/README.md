# Локальная классификация причин через Laya

Используется официальный `convaiinnovations/laya-multilingual` (Apache-2.0), snapshot `1720e3e3357cfe1e281542e223f8273b0890ca34`, runtime `laya==0.3.20`. Источники: https://github.com/NandhaKishorM/laya и https://huggingface.co/convaiinnovations/laya-multilingual . Веса/окружение находятся в `.local/`, не в Git и не в frontend bundle. Собственная RAM/CPU расходуются, платный шлюз не используется.

## Установка на другом устройстве

Нужен Python 3.10+, проверен Python 3.11 на Apple Silicon. Из корня:

```sh
python3.11 -m venv .local/laya-venv
.local/laya-venv/bin/python -m pip install -r backend/laya/requirements-lock.txt
.local/laya-venv/bin/python backend/laya/download.py
npm run dev
```

Скачивание публичных весов требует сети, но не токена. `download.py` закрепляет snapshot, не передаёт разговоры и не читает `.env`. Примерно 614 MiB занимает сам safetensors-файл; окружение и tokenizer занимают дополнительное место. `npm run dev` включает `--local-laya` автоматически при наличии interpreter и весов. Раздельный запуск backend: `node --import tsx src/index.ts --local-laya` из backend/. Включение Laya не разрешает Kimi: прежний one-use gate и запрет чтения токена агентом сохраняются.

## Автоматический путь

После успешного scoring ответа Kimi вызывается `enrichWithLaya`. Выбирается критерий c2 с названием «Выявление потребности»: его evidence-реплики и ближайшие ±1 соседние реплики. Порядок сохраняется, дубли удаляются. Фрагмент может быть применимым или N/A: тема обращения не равна ошибке оператора. Если c2/evidence/client-текста нет, классификация завершается явной ошибкой, не произвольной группой.

В Python передаются только этот текст и RU/KZ/EN. Фрагмент ограничен 12000 символами и доступным токенным бюджетом; слишком большой текст отклоняется без молчаливого обрезания. Worker читает только локальные веса, HF/Transformers offline включены, окружение процесса не наследует API-ключи. Laya выбирает ровно одну из девяти категорий. Ответ проверяется по допустимым ID, распределению и закреплённым model/revision. Не показываем raw probabilities как достоверность: автор предупреждает о некалиброванной уверенности.

Итог и критерии Kimi сохраняются при сбое локальной модели, а `classificationError` сообщает об ошибке. Kimi-category не используется как скрытый fallback. При успехе сохраняется `contactReason.classifier` с model/revision/criterionId/messageIds. Категория и её происхождение не могут быть объявлены Laya самим ответом Kimi. Текущий prompt Kimi всё ещё возвращает свою исходную contact_reason; Laya заменяет её категорию, отдельного запроса к Kimi нет. Перенос исхода допустим только при совпадении категории, иначе исход становится «Неясно».

Для старых сохранённых анализов отдельная кнопка «Определить причину · Laya» вызывает POST `/api/evaluations/:id/classify-reason`; она не запускает оценку Kimi. Endpoint сериализует ручные запросы, сохраняет происхождение либо ошибку и не меняет баллы. Если прежняя классификация уже существовала, при ошибке ручного обновления она сохраняется вместе с видимой ошибкой; автоматически не выдаётся за новый результат.

## Проверка и ограничения

Разработческие проверки на коротких синтетических фразах выявили ошибки классификации. Локализованные RU/KZ описания не оставлены в runtime. Это не независимая оценка качества. Поддержка ввода трёх языков не доказывает точность на финансовых разговорах, смешанной речи или полном DEV-наборе.

Для надёжного применения нужна ручная контрольная разметка RU/KZ/EN и оценка каждой категории. Результат — автоматический выбор модели, не подтверждённая человеком истина. Полные транскрипты не передаются в интернет во время inference. Ошибка или timeout не вызывают автоматического повтора и не списывают новый запрос Kimi.
