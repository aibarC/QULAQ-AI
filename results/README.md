# Результаты для организаторов

`dev/results.json` соответствует приложению «Результаты оценки • Формат JSON 1.0».

- Команда: Amazing Guys; model.mode=external_api; model.name=kimi-k3 (requested и reported совпадают).
-65 диалогов:35RU,15KZ,15EN;60чатов,5звонков.65status=ok,520критериев.
- Источник: сохранённый полный прогон `full65_A_C2_without_ledger`. Это исторический прогон, не новый запуск итогового C6/C7 и не смесь точечных экспериментов. Результаты модели не исправлялись и не заменялись разметкой.
- Все исходные ID и транскрипты сопоставлены с оригинальным DEV. Значения и объяснения сохранены, evidence переведены в1-based позиции полного массива; проверенные диапазоны развёрнуты полностью.
- Все65итогов заново проверены по официальным весам/шкалам/N/A и совпали с сохранёнными. Critical flag соответствует ответу critical и не обнуляет итог.
- Независимая проверка Python Decimal и сравнение всех520значений/причин/evidence прошли. Native backend/браузер выгрузили документ, равный офлайн-файлу;0модельных запросов.
- Контрольный `prod/results.json` пока не создаётся: реальных контрольных результатов нет. Для него обязательны ровно10исходныхID, включая ошибки обработки.

Проверка структурной точности конвертации не утверждает, что все смысловые решения модели верны.

## Повторная офлайн-конвертация того же исторического формата

Из backend (Node24+, зависимости установлены):

```sh
node --import tsx scripts/export-saved-submission.ts \
  --dataset=/private/path/DEV.json \
  --records=/private/path/full65/records.json \
  --responses=/private/path/full65/results.json \
  --output=/private/path/new-results.json \
  '--team=Amazing Guys' --group=DEV --count=65
```

Скрипт принимает criteria-only сохранённые успешные ответы этого исторического формата, проверяет совпадение транскриптов и баллов, не загружает `.env`, не импортирует провайдер и не использует сеть. Уже существующий выходной файл не перезаписывает. Для текущего Workspace, включая ошибки обработки, используйте `POST /api/exports/submission` или кнопку официального экспорта в UI.

В приложении собственные пользовательские правила/веса остаются доступными. Но официальный экспорт требует сохранённую оценку по стандартным восьми правилам: он не переименовывает произвольный новый критерий в один из официальных и не подставляет старую удачную оценку вместо последней ошибки.
